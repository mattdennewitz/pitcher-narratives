<objective>
Build `analyst.py` -- a pydantic-ai tool-calling agent that answers natural-language pitcher questions grounded exclusively in existing pipeline data. Two tools (`get_pitcher_summary`, `get_pitch_detail`) give the agent access to PitcherContext data via `RunContext[QADeps]` dependency injection. Includes static pitch-type synonym mapping, agent factory with caching, and streaming public function.

Purpose: This is the analytical brain behind `pitcher-ask` (Phase 10). The agent decides which tool to call based on the question, ensuring answers are grounded in data and never hallucinated from training data.

Output: `src/pitcher_narratives/analyst.py` + `tests/test_analyst.py`
</objective>

    - Docstring: "Get the full scouting context for the pitcher including all arsenal, execution, and trend data."

    `@_analyst_agent.tool` for `get_pitch_detail(ctx: RunContext[QADeps], pitch_type: str) -> str`:
    - Docstring: "Get detailed arsenal, execution, and platoon data for one specific pitch type.\n\nArgs:\n    pitch_type: Pitch type name or Statcast code (e.g., 'slider', 'SL', 'knuckle curve')."
    - Body: Resolve synonym via `code = PITCH_TYPE_MAP.get(pitch_type.strip().lower(), pitch_type.strip().upper())`. Filter `ctx.deps.context.arsenal`, `ctx.deps.context.execution`, `ctx.deps.context.platoon_mix.splits` by `pitch_type == code`. If no arsenal match, return "No data for {pitch_type} ({code}) in {pitcher_name}'s arsenal. Available pitches: {list}". Otherwise, call `_render_pitch_detail(code, arsenal_match, execution_match, platoon_match)`.

    `_render_pitch_detail(code, arsenal_rows, execution_rows, platoon_rows) -> str`:
    - Build focused markdown with sections:
      - "## {pitch_name} ({code}) Detail" header
      - Arsenal row: usage %, usage delta, P+/S+/L+ values and deltas
      - Execution row: CSW%, zone%, chase%, xWhiff, xSwing, xRV100 percentile
      - Platoon splits: usage by side with deltas
    - Return joined string (~200 tokens)

    Agent factory `_analyst_cache: dict[tuple[str, ThinkingEffort], Agent[QADeps, str]] = {}`:

    `_make_analyst(provider: str = "openai", thinking: ThinkingEffort = "high") -> Agent[QADeps, str]`:
    - Cache lookup by `(provider, thinking)` tuple
    - Validate provider in PROVIDERS, raise ValueError if not
    - Build ModelSettings same pattern as report.py: GoogleModelSettings for gemini, max_tokens=16384 for claude with thinking, standard ModelSettings for openai
    - Use `_analyst_agent.override(model=model, model_settings=settings)` to create a configured agent clone. Cache it and return.

    IMPORTANT: Use `_analyst_agent.override()` (not creating new Agent instances) so the tools remain registered. The override returns a new agent with the same tools but different model/settings.

    `ask_question_streaming(question: str, context: PitcherContext, data: PitcherData, *, provider: str = "openai", thinking: ThinkingEffort = "high", _model_override: Any = None) -> str`:
    - Get agent via `_make_analyst(provider, thinking)`
    - Build `deps = QADeps(context=context, data=data)`
    - Build kwargs dict: `{"user_prompt": question, "deps": deps}`
    - If `_model_override is not None`: set `kwargs["model"] = _model_override`
    - Call `stream = agent.run_stream_sync(**kwargs)`
    - Iterate `stream.stream_text(delta=True)`, print each chunk to stdout, collect into list
    - Print trailing newline
    - Return joined string
